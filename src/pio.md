### PIOA–PIOE — Parallel Input/Output Controllers
*   **Base Address:** `0x400E_0E00` (PIOA), then one port every `0x200`: PIOB `0x400E_1000`, PIOC `0x400E_1200`, PIOD `0x400E_1400`, PIOE `0x400E_1600`
*   **Why It's There:** Controls the chip's pins. Each pin is either handed to a peripheral such as the UART (pin muxing) or used directly as an input or output, for example to light an LED or read a button.
*   **The Problem:** Board initialisation code writes many PIO registers before anything else works, and often reads status registers back to check the result. Most settings come as three registers: one that sets bits, one that clears bits, and a read-only status register showing the result (for example `PIO_PER` `+0x00`, `PIO_PDR` `+0x04`, `PIO_PSR` `+0x08`). Plain store-and-readback gets these wrong, because the status would never change.
*   **Stub Logic:** Every set / clear / status group works as on the real chip. Output data can be set (`PIO_SODR`, `+0x30`), cleared (`PIO_CODR`, `+0x34`) or written directly (`PIO_ODSR`, `+0x38`, only on pins enabled through `PIO_OWER`). Pin levels (`PIO_PDSR`, offset `+0x3C`) read the driven value on output pins and 1 on input pins, as if pulled up with nothing pressing them. The peripheral select registers (`PIO_ABCDSR`, `+0x70` and `+0x74`) and the other configuration registers are store-and-readback. Interrupt status (`PIO_ISR`, `+0x4C`) always reads 0. Every register starts at 0; the real per-port reset values are not modelled.
