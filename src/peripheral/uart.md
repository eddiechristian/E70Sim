### UART0 — Universal Asynchronous Receiver Transmitter
*   **Base Address:** `0x400E_0800`
*   **Why It's There:** The main channel between the firmware and the outside world. Firmware prints through it (boot messages, panic information, debug output) and reads typed input from it.
*   **The Problem:** Before sending, firmware checks the Status Register (`UART_SR`, offset `+0x14`) and waits for the transmitter to be ready; if the ready bit never shows, it waits forever. For input, firmware either polls RXRDY in `UART_SR` or enables the receive interrupt and expects its UART0 handler (IRQ 7) to be called when a byte arrives.
*   **Transmit Logic:** `UART_SR` always reports `TXRDY` (bit 1) and `TXEMPTY` (bit 9). The low byte of every write to the Transmit Holding Register (`UART_THR`, `+0x1C`) goes straight to the host's stdout.
*   **Receive Logic:** Bytes come from a channel that `main` connects to the host's stdin. When the receiver is on (`RXEN` in `UART_CR`, `+0x00`) and the Receive Holding Register (`UART_RHR`, `+0x18`) is free, the next byte is moved into it and `RXRDY` (bit 0) is set in `UART_SR`. Reading `UART_RHR` returns the byte and clears `RXRDY`. Bytes are never lost: one that arrives while `UART_RHR` is full waits its turn, where a real UART would overwrite the old byte and set `OVRE`.
*   **Interrupt Logic:** `UART_IER` (`+0x08`) sets bits in the interrupt mask, `UART_IDR` (`+0x0C`) clears them, and `UART_IMR` (`+0x10`) reads the mask. The UART asks for IRQ 7 for as long as any bit set in `UART_SR` is also set in the mask; the bus passes the request to the NVIC. With `RXRDY` enabled that means "from a byte arriving until the firmware reads it".
*   **Not Modelled:** Baud rate, parity and pins (`UART_MR` and `UART_BRGR` are ignored), and the error flags `OVRE`, `FRAME` and `PARE`, which are never set.
