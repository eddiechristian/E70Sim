### SCB — System Control Block
*   **Base Address:** `0xE000_ED00` (the stub covers up to `0xE000_EFFF`, including the MPU, debug and FPU control registers)
*   **Why It's There:** The Arm core's own control registers, as opposed to a Microchip peripheral: where the vector table is, which faults are enabled, exception priorities, cache and FPU enables, and identification of the core.
*   **The Problem:** Nearly all startup code touches it. It sets the vector table address (`VTOR`, offset `+0x08`), enables the FPU (`CPACR`, offset `+0x88`), and enables the caches by reading the cache size (`CCSIDR`, offset `+0x80`), writing the cache maintenance registers (`+0x250` to `+0x278`) once per cache line, and setting bits in `CCR` (offset `+0x14`). CMSIS also writes exception priorities one byte at a time into `SHPR1`–`SHPR3` (`+0x18` to `+0x23`).
*   **Stub Logic:** Store-and-readback for the configuration registers, with byte and halfword accesses supported. `CPUID` (`+0x00`) reads `0x411FC271` (Cortex-M7 r1p1); the cache ID registers describe two 16 KB caches; `MPU_TYPE` (`+0x90`) reports 16 regions. Cache maintenance writes are accepted and ignored. `AIRCR` (`+0x0C`) needs the `0x05FA` key and stores only the priority grouping. Two things have a real effect: the exception priorities in `SHPR1`–`SHPR3` (top 3 bits of each byte) and the priority grouping decide which exception can interrupt which. The rest has none: there are no caches. The FPU's own registers are here too: `CPACR` (`+0x88`) bits 20 to 23 switch the FPU on, `FPCCR` (`+0x234`), `FPCAR` (`+0x238`) and `FPDSCR` (`+0x23C`) are used by the CPU when saving FPU registers on exception entry, and `MVFR0`–`MVFR2` (`+0x240`) describe an FPv5 FPU with single and double precision. The fault status registers `CFSR` (`+0x28`), `HFSR` (`+0x2C`) and `BFAR` (`+0x38`) are filled in by the CPU when a fault is raised and cleared by firmware writing 1s; `SHCSR` (`+0x24`) bits 16 to 18 enable MemManage, BusFault and UsageFault. A request to reset the system (`AIRCR` `SYSRESETREQ`) is logged but not carried out. `ICSR` (`+0x04`) and `STIR` (`+0x200`), which pend exceptions and report which are pending and active, are handled by the bus, not by this stub.
