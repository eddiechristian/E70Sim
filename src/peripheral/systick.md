### SysTick — System Timer
*   **Base Address:** `0xE000_E010`
*   **Why It's There:** A 24-bit countdown timer built into the Arm core, the same on every Cortex-M chip. Firmware uses it for a regular "tick", typically every millisecond, to keep time, run delays and drive an operating system's scheduler.
*   **The Problem:** Firmware writes a reload value to `SYST_RVR` (offset `+0x04`), clears the counter through `SYST_CVR` (offset `+0x08`), then sets ENABLE (bit 0) and usually TICKINT (bit 1) in `SYST_CSR` (offset `+0x00`). From then on it expects its SysTick handler (exception 15) to run at a steady rate. Delay loops wait on a counter that only the handler advances, or poll COUNTFLAG (bit 16 of `SYST_CSR`); with no timer they never finish.
*   **Stub Logic:** A real countdown, not a fixed answer. It counts emulated clock cycles: after every instruction the CPU reports how many cycles that instruction took (an estimate; see `exceptionInterrupt.md`), and the counter moves by that much. It counts N, N-1, ..., 1, 0 and reloads, where N is the reload value, so it reaches zero every N + 1 cycles. Reaching zero sets COUNTFLAG (cleared by reading `SYST_CSR`) and, if TICKINT is set, makes the SysTick exception pending on the bus; the CPU takes it before its next instruction. Writing any value to `SYST_CVR` clears the counter and COUNTFLAG. CLKSOURCE (bit 2) is stored but changes nothing. `SYST_CALIB` (offset `+0x0C`) reads 0, meaning no calibration value is known.
